SysPerfSight analyzes the HTML report produced by InterSystems IRIS's SystemPerformance utility (known as pButtons on older Caché installations). This page covers how to get the most out of it once you already have a report in hand — not how to generate one.

Export modes

After selecting sections, you can export in three ways:

  • Full report — everything: charts, written insights, raw data, cross-section synthesis, and sensitive-section banners. Best for your own investigation.
  • Charts + Raw — charts and the collapsed raw data, but no written insights or synthesis. Good for a lighter file you still want the underlying numbers in.
  • Charts only — just the charts; no raw data, no insights, no synthesis, and excluded sections are hidden entirely rather than shown as placeholders. Smallest, most shareable output.

Time-range filtering

Some sections (mgstat, vmstat, sar -u, sar -d, iostat) support filtering to a specific time window before export. Enter From/To as 24-hour HH:MM — e.g. 14:30, not 2:30 PM. Leave either side blank for an open-ended range. A range where "From" is later than "To" (e.g. 22:00 to 02:00) is treated as crossing midnight.

This is most useful when you know roughly when an issue occurred and want the charts/insights to focus on just that window instead of the whole collection period.

Sensitive data in the report

Some sections of a SystemPerformance report can contain information you may not want to share outside your organization: license keys, hostnames/usernames, file paths, or full process/task lists. SysPerfSight pre-deselects these sections after upload and explains why — review the flagged sections before exporting if you plan to hand the output to someone else (e.g. a vendor or support case).

Supported formats

SysPerfSight parses both:

  • InterSystems IRIS — reports from ^SystemPerformance.
  • Older Caché — reports from ^pButtons, which use slightly different internal section names for a handful of sections (e.g. ccontrol all instead of IRIS ALL). SysPerfSight detects and maps these automatically — you don't need to do anything differently.

Troubleshooting upload errors

If SysPerfSight reports "No sections found" on upload, the most common cause is that the file was re-saved by a browser (e.g. opened the report and used "Save Page As") instead of being taken directly from where ^SystemPerformance/^pButtons wrote it — browsers can rewrite the HTML structure in ways that look identical on screen but confuse a parser.

  1. Re-upload the original file straight from the manager's directory (or wherever the utility wrote it), rather than a browser-resaved copy.
  2. If the file was emailed or extracted from a zip, confirm it wasn't altered in transit and is still a complete, single .html file.

If it still won't parse, use "Report bug" in the app header — SysPerfSight's error message includes a diagnostic hint (whether the file has no report markers at all, versus markers in an unrecognized layout) that's useful to include.
